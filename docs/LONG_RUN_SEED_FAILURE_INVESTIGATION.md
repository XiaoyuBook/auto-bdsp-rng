# 多轮运行后连续测种失败：排查记录

日期：2026-10-28。依据用户提供的 2026-10-27 日志、同会话轮次截图，以及“失败保护后只重新点开始即可恢复”的补充。

**已确认并修复轮数越限与异常详情丢失两处问题；导致现场持续 Seed 求解失败的具体原因尚未确认。本记录中的流程复现主动注入了求解错误，不能视为复现了真实设备上的求解故障。**

## 为什么“重新点开始能恢复”是重要线索

| 状态 | 同一任务中自动重试 | 手动重新开始 |
| --- | --- | --- |
| Runner / Worker | 继续使用当前实例和线程，清理当前轮次数据 | 新建实例和线程 |
| 服务闭包和运行取消对象 | 继续使用本次任务建立的服务 | 重新建立服务与取消对象 |
| 测种配置 | 使用任务启动时读取的配置快照 | 重新读取配置 |
| 缩放恢复 | 后续轮次在测种脚本前尝试检查、恢复 | 从测种脚本开始的新任务首轮不走这一额外检查 |
| 原始测种求解 | 本次眨眼类型、间隔与 NPC 参数 | 同样只使用本次输入，不接收旧 Seed 或旧 Adv |

这些确实是代码中的运行边界差异，但目前没有证据确定是哪一项导致现场持续失败。不能仅凭“重新开始恢复”就宣称某个变量残留，或通过任意清空状态认定已经根治。

另已核对：捕捉入口会清理本次捕捉取消标记；控制器为每次脚本建立新的取消事件，并在脚本结束时清理按键和运行状态。它们是检查过的重置点，并不等于已排除所有现场时序问题。

## 实际做过的复现与核对

### 1. 复现轮数越限

用真实状态机运行“循环 10 次”：前 6 轮正常完成撞闪；第 7 轮使用日志中的目标推进与过帧量，随后主动注入连续求解失败。长脚本时间由虚拟时钟推进，不做九小时实机执行。

- 修复前：启动第 1–11 轮，前 6 次撞闪完成；第 7、8、9、10、11 轮测种失败，最后由连续五次失败保护停止。
- 修复后：只启动第 1–10 轮；第 10 轮仍失败时停止，提示达到设定轮数，并保留最后一次求解诊断。
- 同一路径只注入一次错误时，当前 Runner 能在下一轮继续，最后按设定轮数结束。
- 真实 Worker、主窗口和历史事件串联测试也验证了没有第 11 轮，最后错误属于第 10 轮，内部输入不会进入用户日志。

### 2. 实际求解器是否会被一次失败永久污染

使用实际 Project_Xs 求解代码和 Xorshift 生成的可解观测序列：连续求解成功 6 次，修改一个观测位让求解失败，再输入原本正确的序列，立即得到与原先相同的结果。这个测试没有重启进程或重建求解模块。

它说明该测试中不存在“一次失败后求解器永久变坏”，不能据此排除真实样本、运行环境或恢复动作触发的其它问题。

### 3. 核对真实服务闭包

另外使用实际自动测种服务闭包，替换设备采集和求解返回值，比较连续成功、一次失败、原服务重试和重建服务后的行为。9 次调用收到的序列与 NPC 参数保持一致，失败后没有在该测试中留下取消标记或脚本占用。

该测试仍不等于现场数据重放；它用于避免将“替换整个服务的模拟通过”误当作“已检查服务内部初始化”。

## 本次确定的修复

1. 固定轮数上限只在正常结束分支检查，失败换轮分支忽略上限。现在失败换轮也检查，达到上限后保留失败终态，不会继续开始下一轮。
2. 补救测种传入的 `details` 被归入未使用的进度参数，没有进入日志；部分校正与重测失败转入下一轮时也只剩普通字符串。现在接收并保留这些异常详情及原因链。
3. 采集完成后增加 DEBUG 求解输入记录，成功和失败都保存本次序列、NPC、实际配置、准备动作、视频代次、运行/捕捉取消状态和脚本占用状态。
4. 求解异常另附原始输入与异常所在函数、行号，保留原有异常文本与兼容关系。所有新增参数仅进入诊断视图和启用的磁盘日志，默认用户文案仍为业务提示。

第三、四项是定位手段，不能写成“持续测种失败已经修复”。本次继续使用原有 Seed 求解算法。

## 下一步如何准确定位持续失败

使用包含本次诊断的代码运行。若再次出现问题，在完整日志中选择“全部诊断”，来源为“自动定点”，对比：

- 最后一次失败之前的“测种求解输入已记录”。
- 手动重新开始后首次成功之前的同名记录。
- 失败消息的“原始诊断”，包括异常所在函数及原因链。

导出时使用“全部诊断”，或保留对应磁盘日志；仅复制用户摘要没有求解输入。

应先重放同一次失败输入，再对比两次运行的参数与准备动作：同输入在新旧调用环境的结果是否相同；NPC、配置、准备动作是否发生变化；运行取消或脚本占用是否异常。数据可以离线重复求解，减少反复跑长流程的成本。

尤其要区分异常位置：`gauss_jordan` 的断言与 `recov` 的校验断言不是同一类问题，旧包装都可能只显示“无法校验 Seed”。新增诊断保留具体位置，避免继续猜测。
