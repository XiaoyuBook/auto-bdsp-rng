## 首次使用

1. 点击主窗口顶部的视频源状态（如“视频源 未连接”），在“视频源设置”中选择采集卡和采集方式后连接。优先使用“Media Foundation（推荐）”，遇到设备兼容问题时再尝试“DirectShow（兼容）”。软件会记住选择，但下次启动仍需手动连接。
2. 在任务页选择 Seed 配置，点击右侧编辑按钮展开参数。在右侧视频中框选眼睛 ROI、截取眼睛模板，使用“测试捕捉”验证当前参数，再点击“保存”。御三家全自动固定使用内置配置和模板，仅调整 ROI 与匹配阈值，详见[专用流程](#御三家全自动)。自动 TID 的测试会执行 TID/SID 测种，过场校正配置的测试会执行校正。
3. 点击顶部“伊机控”状态入口选择串口并连接单片机，再用短脚本或键盘控制确认按键能够正常发送。纯按键脚本无需连接视频源，实际执行搜图或 OCR 时才需要可用画面。
4. 切到顶部“OCR 设置”标签页，在“宝可梦信息”中运行“测试全部”，检查性格、个性和六项能力值；两个判闪计时区域需单独识别或校准。十项默认区域会在首次使用时自动加载，1920x1080 标准画面通常无需手动导入；画面比例、语言或 UI 位置不同则应重新框选。
5. 确认游戏站位、队伍、脚本参数、delay 策略和基准 delay 后，再启动自动流程。内置脚本不是对所有设备都通用的零校准配置。

v3.4.0 移除旧分步引导模式，首次启动在欢迎页点击「进入工作区」即可使用。配置顺序可按上面的步骤操作，启动流程会自动核对设备、眼图、脚本和 OCR；旧版引导进度不再触发任何流程。顶部「通知」中的 QQ 注册与绑定教程保留。

## 工作区

| 工作区 | 用途 |
| --- | --- |
| 自动定点乱数 | 串联测种、目标搜索、过帧、校正、撞闪、OCR 判闪和反查。 |
| 自动 TID 乱数 | 串联 TID/SID 测种、Display TID 搜索、目标帧等待和取名脚本。 |
| 定点数据区 | 按 PokeFinder 口径生成和筛选定点/游走候选，并提供个体值计算。 |
| 脚本编辑区 | 编辑、运行和录制 EasyCon 风格脚本；控制入口在右上角的“伊机控”菜单。 |
| 轮次记录 | 查看每轮结果、候选、Seed 和详情；“查看本轮日志”打开独立完整日志窗口。 |
| OCR 设置 | 设置宝可梦信息、判闪计时和 Display TID 的识别区域，直接在右侧视频框选和测试。 |

“工具 → 手动测种与校正”保留配置浏览、新增、普通 Seed 捕捉、TID/SID 测种、校正和活帧时间线；点击“返回任务”回到之前的工作区。

界面采用冷白与翡翠绿配色，随包提供 MiSans 字体，无需联网安装。左侧工作区随页面切换，右侧固定显示视频和实时日志。窄屏时左侧配置控件换行或纵向排列，两区可独立滚动并记忆分栏比例。自动定点在同一页显示目标与流程状态卡片，下方按「基础配置」「闪光与反查」「过场策略」「同步与续搜」组织参数与脚本；状态卡片的「详情」打开实时运行数据窗口。自动 TID 继续使用任务设置与运行数据分页。启动流程会自动完成设备、脚本和 OCR 检查，缺少配置时可从相应空状态进入处理。

从 v3.3.3 起，基础控件与菜单、折叠箭头采用统一风格，减少不同 Windows 版本带来的外观差异。实际字号和整体尺寸仍受 Windows 显示缩放与软件界面倍率共同影响。比较两台电脑的界面时，应同时对齐窗口大小、任务运行状态以及 Seed 信息和脚本卡的展开状态；运行卡展开或窗口较矮时，下方内容可能需要滚动查看。

界面会记忆主要设置和窗口位置。可在“帮助 -> 界面缩放”中选择自动适应所有屏幕或 `50%-125%` 手动倍率；自动模式按所有已连接显示器中最受限的工作区计算，必要时可低于 50%。`Ctrl+-` / `Ctrl++` 以 5% 调整，`Ctrl+0` 恢复 100%。缩放设置在重启后生效；选择立即重启后会等待后台任务退出，取消关闭则在下次启动时生效。数值输入固定使用 ASCII 数字和 `.` 小数点，避免受 Windows 区域格式影响；输入框和下拉框忽略滚轮改值，滚轮继续用于页面滚动。

## 视频源与预览

视频源和实时日志固定在主窗口右侧，切换任务、编辑配置或打开手动测种工具时都可持续查看。拖动中间分隔线可调整右栏宽度，并保留到下次启动。实时日志展开时，视频高度随右栏宽度和画面比例自动调整，日志占用其余空间。

视频画面左上角叠加当前 RNG 帧数（advance）和可选中复制的 Seed0 / Seed1；右上角在匹配有效时显示实时分数和可调整的识别阈值，捕捉期间显示眨眼进度。窄视频下两组信息自动上下错开。框选眼睛、ROI 或 OCR 区域时隐藏叠加信息；自动流程重新捕捉期间隐藏上一轮 Seed，取得新结果后恢复显示。这里的“当前帧数”是 RNG 推进数，不是采集卡帧率。信息只叠加在界面上，不写入原始画面或截图。视频下方保留连接状态与分辨率。

右侧“实时日志”显示最近 300 条运行摘要，正文按消息分组，来源、轮次和时间使用次级文字，警告与错误另行标注。可按来源筛选、暂停自动跟随，也可折叠和恢复。折叠期间继续收集消息，恢复后保留来源与跟随设置。“查看完整日志”打开独立窗口并带上所选来源，默认包含该来源的整个会话。日志筛选不会清除当前会话数据。

实时区只显示经过整理的用户提示，不直接显示内部参数、文件路径、异常堆栈和脚本原始输出。尚未整理的问题会显示简短提醒；需要排查时，可在完整日志中选择“全部诊断”或主动展开详情查看原文。

任务中的 Seed/过场校正配置右侧编辑按钮会在当前页展开配置编辑区，高级时序参数默认展开。识别参数区保留框选与截取按钮，眼睛模板文件名和 ROI 坐标不再显示；匹配阈值通过视频右上角调整。保存会影响所有使用同一份文件的任务；取消会放弃本次参数和框选修改。编辑期间先使用“测试捕捉”验证，再保存或取消后启动任务。眼睛框选与截取仍在右侧视频上操作，测试进度与 Seed 结果也显示在视频上。

采集卡主路径使用独立 Capture Broker 独占设备，并把同一份最新原始画面提供给主预览、独立预览、Seed/TID 捕捉、OCR 和伊机控搜图。各消费者可以同时读帧，识别框只绘制在显示副本上，不会污染后续识别画面。

- Broker 默认按 1920x1080、MJPG、30fps 请求采集卡画面；主预览常驻刷新。
- 顶部“视频源设置”提供 Media Foundation、DirectShow 和自动选择三种采集方式。
- 刷新设备列表或切换采集方式时显示刷新状态，界面仍可操作；连续切换只应用最后一次选择的列表。
- 主预览和独立预览都可切换识别框；独立预览还可单独设置始终置顶。
- 眼睛模板/ROI 配置错误与视频源无帧会分别提示，便于判断应重新框选还是检查设备连接。
- 软件同一时间只维护一个共享视频源/Broker；连接期间所选采集卡由它独占，关闭程序时会一并释放。

Project_Xs 的窗口捕获兼容路径仍支持 OBS 投影窗口，并通过 Windows Graphics Capture 读取画面。OBS 窗口不需要置顶，但必须保持打开且不能最小化。OBS 窗口捕获不属于共享采集卡 Broker，二者不要混为同一种视频源。

框选眼睛、ROI、OCR 区域或显示 OCR 范围时，没有缓存画面会先等待视频首帧。可用状态栏的取消按钮或按 `Esc` 取消等待或框选，再次点击同一框选/显示按钮也会取消等待。TID OCR 识别期间按钮变为“取消识别”，取消、关闭或切换视频源后不会显示旧任务的结果。

## Seed 捕捉与校正

- 复用 Project_Xs_CHN 的玩家眨眼、宝可梦眨眼、Seed 恢复、活帧计数和 timeline 逻辑。
- 普通 Seed 捕捉得到 `Seed[0-3]`，并自动转换为 BDSP 定点搜索使用的 `Seed[0-1]`。
- TID/SID 测种固定按 Project_Xs 原版流程捕捉 64 次宝可梦眨眼，并启用对应的 Munchlax 活帧模型。
- 支持普通校正和 `1 PK NPC` noisy 校正。计算优先使用 C++ 原生实现；原生不可用、输入不支持或未命中时回退到 Python 实现。
- 停止手动捕捉或自动流程也会取消正在计算的校正，包括原生与 Python 回退搜索；停止后保留已接受的 Seed 和帧位置，不再扩大范围重试，可重新启动。
- 过场脚本执行后的校正采集 20 次玩家眨眼，按 Project_Xs 原版界面的默认范围搜索原始 Seed 的 0～1,000,000 帧，支持存在 1 个宝可梦 NPC 的情况。
- 自动定点校正优先搜索预计帧数附近的范围；未命中时复用同一组眨眼观测扩大范围，普通校正回退到当前配置的最大帧数，`1 PK NPC` 校正分窗口搜索。这样可减少长距离过帧与预估值偏差较大时的漏搜；仍受眨眼识别质量和配置搜索范围影响。
- 捕捉前后会协调预览和 ROI 状态，框选确认或捕捉结束后自动恢复实时预览。

捕捉亮屏保活的范围是明确受限的：仅在 20、40、64 次眨眼捕捉过程中，每完成 10 次且捕捉尚未结束时，通过已连接的伊机控短按一次 `L`。发送失败不会中断测种。过帧脚本运行期间以及自动 TID 等待目标 Adv 期间不会持续发送保活按键。

## BDSP 定点数据

存档区显示名称、游戏版本和 TID/SID/TSV，点击“管理”修改存档及护符设置。目标、队首、Seed 和搜索范围在同一表单中连续显示，无需切换分页；“追加帧数”从初始帧继续搜索并包含首尾，设为 0 时只生成初始帧。

“筛选条件”默认收起，展开后可按六项 IV 的下限/上限、特性、性别、性格和异色类型筛选；身高和体重从“体型筛选”展开。收起仅改变显示，已设置的筛选仍参与生成。“显示能力值”位于结果表上方；宽栏直接提供复制、导出 CSV，窄栏可从“更多”使用相同操作。

点击“生成”完成后收起查询条件，显示本次目标和搜索帧范围，悬停摘要可查看 Seed 和 Offset。自动刷新保留查询条件的展开状态；大范围后台查询的摘要对应启动时的参数。窄窗口中条件区可独立滚动，结果表保留查看空间。

生成在后台进行，可从结果区“更多 → 取消搜索”停止；再次生成或收到新 Seed 时，以最新查询为准。超过 200 条的结果每页显示 200 条，超过一万条时排序和前缀查找也在后台进行。排序覆盖全部结果，输入前缀可定位到其它页；切换能力值显示或排序时保留当前选中的个体。表格右键复制选中行，结果区“复制”和 CSV/TXT 导出保留完整结果。

大量结果的完整复制和导出会在后台准备，按点击时的结果、语言和能力值显示保留原始生成顺序。准备期间再次点击相应按钮可取消；取消、准备失败或收到新结果时保留原剪贴板和已有导出文件。导出进入“保存中”后完成本次保存，此时不能取消；关闭程序会等待保存完成，未及时完成时保留窗口供稍后重试。

- 支持初始帧、搜索范围、Offset、队首特性、游戏版本、TID/SID/TSV、闪符等参数。
- 支持定点与游走目标、固定 IV、性格、特性、性别、体型和异色类型筛选。
- “同步”队首可从子菜单直接选择 25 种性格，也支持迷人之躯。
- 候选表可排序、复制选中行并导出 CSV/TXT，支持列显示控制、筛选方案和中文化结果；切换能力值显示时保留现有表格，减少大表卡顿。
- 个体值计算器使用 PokeFinder 公式，支持中文宝可梦名和未知性格的多倍率反算。
- 定点生成和搜索优先使用 C++ 原生扩展，并保留 Python 回退路径。

## 自动定点乱数

自动定点将实机步骤组织为一个可停止、可循环的状态机：

```text
测种 -> 搜索候选 -> 过帧/过场 -> 校正或重新测种 -> 撞闪
     -> OCR 判闪 -> 录像/反查/逃跑续搜 -> 完成本轮或进入下一轮
```

- 支持单次、循环 N 次和无限循环，可从“测种”“捕获 Seed”或“校正”三个起点开始。
- 支持多个目标及各自筛选条件，并记忆最近使用的目标组合。
- 自动定点与 TID 的脚本下拉框支持搜索：展开后输入脚本名称关键词，按名称包含匹配筛选，英文不区分大小写；点击结果或用上下键选中后按 Enter 确认，Esc 取消。展开时会重新扫描外层 `script` 目录，清空关键词可恢复完整列表。
- “保存配置”统一保存当前任务参数和全部脚本选择，标题处显示未保存状态；开始流程时也会保存，并使用启动时的常规配置。脚本内容仍需在脚本编辑器中单独保存。本轮 delay 在轮次开始时冻结。
- “基础配置”中的“校正与补救设置”集中配置校正帧数上限、普通校正最大尝试次数、普通校正失败策略和重测 Seed 最大尝试次数。“过场策略”单独配置过场校正配置、过场预留帧数与过场脚本；预留帧数修改后通过“保存配置”保存。设置从下一次启动自动流程起生效。
- 校正帧数上限默认 900,000，设置窗口最多可填 1,000,000：普通流程的本次过帧量不超过该值时执行校正，超过时完整重测 Seed 并重新搜索目标。普通校正默认最多尝试 2 次；连续失败后可直接进入下一轮，也可先按配置次数完整重测 Seed，成功后留在本轮并废弃旧目标。
- 过场预留帧数默认 500,000，用于决定何时执行过场脚本。任何过场脚本运行后只允许固定最多 2 次过场校正，不会原地完整重测 Seed；校正失败、过帧超过上限或目标已不可达时直接运行测种脚本进入下一轮。
- “基础配置”中的 delay 策略按钮显示当前策略与下轮预计值，运行详情可查看本轮冻结值；设置窗口可选择固定 delay、上次实际 delay、众数、中位数、滚动平均值、指数平滑、截尾平均和密集区间 8 种策略。默认继续使用固定策略；原 `fixed_delay` 设置作为基准 delay 保留，并在动态策略没有有效样本时回退使用。
- delay 配置和样本按当前精灵独立、跨启动保存，切回精灵时自动恢复，不按脚本或筛选条件拆分。部分精灵可提供“推荐 delay”；使用推荐值只会填入基准值草稿，没有推荐数据时显示“暂无推荐”。
- delay 样本只来自已启用、成功且返回非负 delay 候选的自动反查，使用固定策略时也会记录；并非每次遇到精灵都会产生样本。每轮候选去重后成组保存，并记录稳定轮次号和时间。设置窗口显示最近 5 轮，完整记录每页 10 轮；单轮可划除并用回转箭头恢复，划除记录保留在原位但不参与计算，也可清空当前精灵的全部样本。
- 多候选轮次默认忽略，也可设置为每轮总权重为 1、由轮内候选均分；“上次实际 delay”始终跳过多候选轮，其他统计策略使用最近 N 个有效轮次。统计窗口只限制参与计算的样本，不会自动删除更早的历史。
- 每个新轮次开始时会同时冻结目标精灵和本轮 delay；同轮的重搜、逃跑续搜和补救测 Seed 都继续使用该精灵对应的值。运行中修改策略、划除记录或反查得到新样本只重算下轮预计值，不改变本轮冻结值。
- 后续自动轮次可在测种脚本前识别缩放/锁定提示，并通过双 HOME 尝试恢复正常画面。
- 可选“逃跑续搜”：明确未出闪且仍有后续候选时运行逃跑脚本，回到可校正位置后继续本轮搜索。
- OCR 可识别判闪对话、能力值、性格和个性，用于闪光判断与自动反查；闪光判定间隔可先单独校准。
- 自动反查会先使用框选的个性区域；识别文本无法对应标准个性时自动改用全图重试。个性是可选筛选条件：匹配成功时用于缩小候选；全图仍无法匹配时提示“个性匹配失败”并跳过个性过滤，继续按性格和能力值反查。
- 自动反查最终只有一个匹配个体，且该个体为星闪或方闪时，即使此前 OCR 判为未出闪，也会记录为出闪并立即结束自动流程，保留当前画面供人工确认，同时提示检查判闪阈值。此保护在实际完成自动反查后生效；多个候选不会按唯一闪光处理。
- 选择草苗龟、小火焰猴或波加曼时，判闪计时会改为“去吧/上吧”到战斗按钮出现；其他普通目标继续使用“出现了！”到“去吧/上吧”。
- 艾姆利多和克雷色利亚的游走流程会先确认进入战斗，再开始判闪 OCR 计时。
- 判定出闪后可向伊机控发送 Capture 录像指令；候选、本轮使用的 delay 和反查得到的实际 delay 会写入历史记录。
- 主动停止会尝试结束当前脚本并记录停止阶段，且不会触发后续重试或测种脚本。普通校正按用户配置的次数和失败策略处理；过场校正固定最多 2 次并直接进入下一轮。连续三次捕获到相同 Seed 且搜索零候选时会停止，并提示重新框选眼睛模板和 ROI。

脚本时序口径如下。撞闪脚本声明整数 `_闪帧` 时，该帧数由脚本内部等待；未声明时由软件等待到启动点后直接运行脚本：

```text
round_delay = 本轮开始时由 delay 策略计算并冻结的值
script_wait_frames = integer _闪帧 when declared, otherwise 0
trigger_advances = raw_target_advances - round_delay - script_wait_frames
remaining_to_trigger = trigger_advances - current_advances
```

### 御三家全自动

在自动定点的目标中选择同一种草苗龟、小火焰猴或波加曼，在「任务配置 → 基础配置」的「基础脚本」中勾选「御三家全自动」。软件会自动绑定内置御三家测种和反查脚本，无需选择过帧或撞闪脚本；未出闪后自动反查，并按单次、指定次数或无限循环继续。反查脚本与脚本库 `bdsp-starter-reverse 0.0.5` 一致。

从「开始」运行内置测种脚本，或停在「怎么回事？刚才那两人……」并选择「从捕获 Seed 开始」。御三家全自动固定使用 `config_starter.json`，请在这个对话界面的放大模式下确认眼睛识别正常、能够捕捉 Seed。点击配置右侧编辑按钮时，仅允许调整右侧视频的匹配阈值和眼睛 ROI；眼睛模板和其他参数锁定，保存只修改阈值和 ROI。普通任务与自动 TID 的配置选择不受影响，关闭御三家全自动后恢复普通配置编辑。

采集复用固定配置的眼睛模板、保存后的 ROI/匹配阈值和视频源，临时应用 Time Delay `0`、Advance Delay `41`、Advance Delay 2 `48`、NPC `1`、Timeline NPC `-1`、Pokémon NPC `2`；固定时序不写回配置文件。测种后复用缩放检测，需要时双 HOME 恢复。

只在起点、「博士……」、「搞什么啊！」和「要选哪一只？」四处确认 OCR，中间按录像验证的固定次数与节奏推进。搜索候选时预留退出放大模式、OCR 确认和起点至博士对话的时间，跳过来不及的目标。在目标前固定 **200 帧**启用 Timeline，两次归零由计时器按 A。精灵球界面提前移动到目标光标，在目标前本轮 **delay** 帧发送 `A → WAIT 800ms → UP → WAIT 100ms → A`，点击均为 50ms。

每轮开始冻结该御三家的 delay 策略，反查样本供下一轮使用；固定 200 帧窗口要求实际 delay 小于 **78 帧**。首次启用且没有已配置 delay 或样本时预设为 **66 帧**，已有设置继续使用。御三家闪光阈值默认 **5 秒**，可手动调整并独立保存，关闭御三家全自动后恢复普通定点的阈值；旧版御三家默认的 4 秒会更新为 5 秒，其他已保存的自定义值继续使用。判闪使用「去吧/上吧 → 战斗」两个 OCR 区域。疑似出闪后录像并停止；判定未知或关键对话失败时停止；错过时机不选精灵，按循环设置结束或重新测种。

## 自动 TID 乱数

自动 TID 的完整流程为：

```text
运行 id 测种脚本 -> 捕获 TID/SID Seed -> 生成 ID 数据
-> 搜索目标 Display TID -> 等待 target Adv - delay -> 运行取名脚本
```

- 支持“从测种脚本开始”和“从捕获 Seed 开始”两种入口，捕获结果会回填到页面。
- 目标池可同时保存多个 0-999999 的 Display TID；同一轮命中多个目标时选择 Adv 最早的一项。
- 输入目标后点击 `+` 或按回车才会加入目标池。添加、删除目标后，“开始”按钮与菜单会同步刷新；按钮不可用时可悬停查看原因，并在完整日志窗口查看对应的按钮状态记录。
- 内嵌 ID 表显示 `帧数 / TID / SID / TSV / Display TID / 累计用时 / 预计到达时间`。累计用时按 Project_Xs 小卡比兽眨眼模型、从本轮测种计时起点计算，各帧间隔并非固定的 `1/60` 秒。
- 预计到达时间使用固定本地日期，如 `2026.08.11 17:40:40`；实际推进后显示“已过”或“当前帧”，悬停可查看原预计日期。手动输入 Seed 仅生成相对用时，真实测种后才附加日期基准。
- 顶部“距取名启动 · 预计”显示倒计时（如 `00:43.5`），下方显示触发帧和本轮 delay。仅倒计时持续刷新，表格状态随帧进度更新；停止、重测或进入取名阶段后结束该次倒计时。
- 用带数量的“全部 TID / 仅目标 TID”切换查看完整数据或所有匹配目标，点击“定位目标”跳转到目标行。运行中使用启动时的目标配置，编辑目标池不改变本轮筛选。
- 超过 200 条时使用每页 200 条的分页表；大量结果的排序、筛选和前缀查找在后台完成，范围包含所有页。“定位目标”可自动切回全部 TID 并跳到目标所在页。
- 支持选中行复制；“复制全部”和“导出全部 CSV”始终包含全部生成结果，并按原始生成顺序保留累计用时与固定日期，不受仅目标筛选影响。CSV 的首列仍为 `Adv`。
- 大量 ID 数据的复制与导出在后台准备，按钮显示取消入口；时间原点和日期以点击时为准，当前帧的“已过／当前帧”提示不会写入完整结果。导出进入“保存中”后完成本次保存，关闭程序会等待保存结束。
- “保存配置”统一保存目标、任务参数与脚本选择，基础脚本可折叠；开始流程或正常退出主程序时也会保存，下次启动恢复。脚本内容在脚本编辑器中单独保存。
- 未在搜索范围内命中、delay 大于目标 Adv 或已错过启动帧时，可重新运行测种脚本进入下一轮。
- 后续轮次运行测种脚本前也会检测缩放/锁定提示，并通过双 HOME 尝试恢复正常画面。
- 取名脚本在 `目标 Adv - delay` 触发；等待阶段使用 Project_Xs 的 TID/SID 活帧模型，不会主动发送控制器保活按键。触发前会核对实际 Adv；若搜索或等待唤醒时已超过触发帧，不再补执行取名脚本，而是按流程进入下一轮或结束，并记录实际帧数。
- 停止和异常记录会保留轮次、阶段、Seed、目标 Adv、实际等待和停止来源，便于区分用户停止、系统关闭、脚本问题和画面中断。

## OCR

顶部“OCR 设置”是独立标签页，包含“宝可梦信息”和“TID”两项。右侧视频和日志持续显示，可直接框选、显示区域和测试识别；修改区域后自动保存，切换页面保留识别结果。自动定点工具栏的 OCR 弹窗入口已移至此页，启动检查中的 OCR 快捷入口也会切换到对应设置。

Windows 绿色包已内置 PaddleOCR/PaddlePaddle 和项目固定的模型，普通用户无需另行安装。OCR 模型按第一次识别、测试或自动流程的实际需要预热，不会在每次启动时无条件占用资源。

v3.4.0 支持中文及含空格的安装目录、图片和眼睛模板文件名，无需修改 Windows 区域设置。部分原生 OCR 加载器仍要求英文路径，软件会自动把需要的模型或语言数据复制到可写的英文缓存目录，校验内容后复用；首次准备缓存可能稍慢。只读安装目录不会被用作必须写入的缓存位置，已配置且可写的 `PADDLE_PDX_CACHE_HOME` 会继续使用。

如果缓存目录均不可写、包含中文或路径过长，日志会给出具体原因。可将环境变量 `AUTO_BDSP_RNG_NATIVE_CACHE_HOME` 设为自己有写入权限的纯英文绝对路径（例如 `D:\BDSP-OCR-Cache`），重新启动后再预热。正式包缺少或损坏模型时应重新完整解压安装包；缓存不会替代对随包模型的检查，也不会自动下载模型修补安装。

OCR 区域设置包含十项内置默认区域：性格、个性、六项能力值、判闪对话区域和御三家战斗区域。每项都可以单独框选、显示、识别和重置；“测试全部”会自动翻页测试前八项精灵信息，两个判闪计时区域需单独识别或使用闪光判定校准。默认区域按 1920x1080 画面校准；自定义区域无效时，判闪对话区域会回退到画面下半部，御三家战斗区域会按当前分辨率定位右侧战斗按钮。

识别流程兼容简体和繁体中文常见文本差异，并统一复用共享 OCR 实例，避免自动流程、手动测试和闪光判定同时创建模型。

## 伊机控与脚本

产品主路径使用项目内置的 Python 原生 EasyCon 运行时：连接后长期保持同一串口，脚本页面、自动定点、自动 TID、OCR 翻页、虚拟手柄和捕捉亮屏保活共享该连接。脚本直接从编辑器内存执行，不会生成 `script/.generated` 运行副本。

串口连接恢复使用 3.3.x 的主线程打开与握手方式，连接时界面可能短暂停顿，期间连接按钮禁用；正常按键收发仍由独立线程执行。断开与退出清理继续在后台完成。若连接意外丢失，运行日志会附上串口、波特率、收发/报告线程状态和原始异常，便于定位故障。

- 支持 `.txt` / `.ecs` 文件加载、编辑、保存、未保存提示、参数扫描和 `Ctrl+S`。
- 紧凑工具栏提供脚本菜单和临时脚本库面板，可浏览当前脚本及 lib 库，单击预览，双击或回车打开编辑；切换前可保存、放弃或取消未保存草稿。执行跟随与跨库浏览不会覆盖当前编辑内容，运行输出默认折叠，可展开查看。
- 运行时显示实际执行行、动作与等待剩余时间、循环轮次及跨库调用位置，可开启“跟随执行”或点击“定位执行行”；停止和完成后保留最后位置。
- 编译或执行报错时可定位主脚本或库文件的对应行，输出详情保留原始错误文本；定位和查看库文件不会覆盖当前未保存草稿。
- 脚本编辑区手动运行的脚本可暂停并修改未执行的代码，点击“继续运行”直接编译当前草稿，无需先保存。WAIT 立即暂停并保留剩余时间，按键和摇杆在当前动作完成后暂停；继续后保留变量、循环次数及调用进度。已执行或正在执行的语句、已进入的循环/函数头和已加载的库集合受到保护，不合法修改会保持暂停并提示原因。自动乱数流程不提供此操作；暂停脚本不会暂停游戏或 RNG。
- 纯按键、等待及循环脚本无需视频源。实际执行搜图或 OCR 语句时才读取画面；包含手柄操作的脚本仍需连接伊机控。
- 右上角“伊机控”入口持续显示未连接、连接中、已连接或故障状态，菜单提供“连接设置”“打开 / 关闭虚拟手柄”和“按键映射”。这些操作在任意标签页都可使用；“连接设置”会打开独立窗口，用于选择和刷新串口、连接或断开设备。
- 菜单展开时，方向键用于菜单导航，`Esc` 收起菜单；收起后恢复原来的控制 / 待机状态，录制保持原状态。`Ctrl+Esc` 仍可彻底关闭手柄。
- 支持键盘控制、按键映射、按下/释放和摇杆输入；映射窗口中可右键对应按键并选择“删除映射”。Windows 下启用后可在软件失去焦点时继续控制。按 `Esc` 会立即在启用与待机之间切换，按 `Ctrl+Esc` 会彻底关闭并隐藏自动出现的手柄状态悬浮窗；待机时普通映射键正常透传，仅保留快捷键监听。悬浮窗复用原版 EasyCon 的 `100x100` VPad 素材与绘制坐标，会显示实际发送给单片机的按键和摇杆报告，也能显示脚本操作。
- 连接后，从“伊机控”菜单打开虚拟手柄即可启用键盘控制；左键单击浮窗或按 `Esc` 切换控制 / 待机，右键拖动、右键单击复位，中键或 `Ctrl+Esc` 关闭。浮窗独立于脚本编辑区，不挤占编辑器。
- 脚本工具栏提供“开始录制”；录制期间显示“暂停 / 继续录制”和“停止录制”，也可从右上角“伊机控”菜单暂停或停止。命令和等待时间实时追加到当前草稿末尾，停止时不重复插入。暂停录制仍可控制游戏；切换为手柄待机、关闭手柄或断开连接会结束录制。开始页面脚本或自动流程时会停用键盘控制并释放当前输入，脚本结束后需由用户手动重新启用。
- 支持 `.IL` 模板搜图、XY/Laplacian 边缘匹配、`TesserDetect`、`IMPORT` 和脚本目录下的 `lib/`。
- 暂不支持 `.ILX`。
- 同一时间只运行一个脚本；停止、异常或断开时会释放残留按键和摇杆状态。
- 旧 CLI/Bridge 源码仅作为兼容与回归参考保留，不是正式包的默认运行路径。

正式包只使用 exe 同级的 `script` 目录，不再使用 `_internal/script`。启动时会清理旧内部目录：与外层脚本内容相同的副本直接删除，独有或内容不同的文件备份到 `script/.legacy-internal-backup`，不会自动参与执行；需要恢复时请对比后手动复制到外层 `script`。

## 轮次记录与日志

主导航的“轮次记录”直接展示轮次内容：可按运行和轮次选择记录，详情展示所选轮次的 Seed、锁定 Adv、警告、候选快照和处理结果。候选表包含状态、Adv、异色、性格、个性、六项 IV、特性、性别、EC、PID 和体型；锁定目标、同步来源和异色单元格会分别标记。轮次内容可搜索、筛选、复制和导出，并区分“无候选”与“未出闪”。点击“查看本轮日志”打开完整日志窗口，只显示所选运行与轮次的日志。

轮次列表、候选表及处理详情每页最多显示 100 条，可通过翻页查看较早内容。分页不截断搜索、复制或导出：完整快照使用会话临时存储保存，退出后自动释放；需要留存时请在退出前导出。临时存储写满时会回滚失败写入，保留旧记录并转为内存保存，同时显示提示。自动流程在后台整理候选快照并归档，待归档或归档失败后仍可直接翻到任意候选页，表格只生成当前页的内容；归档积压不会阻塞自动流程，清空历史也不会停止搜索或丢弃反查对当前个体的判断。完整历史搜索在后台完成，输入新关键词后只应用最新查询；大量文本复制和导出会显示准备状态，完成后自动提供完整结果。清空或关闭会取消尚在准备的复制、导出，保留已有剪贴板和导出文件；导出进入“正在保存…”后会完成本次保存并报告结果，关闭程序会异步等待保存终态。

“完整日志”使用可调整大小的非模态窗口，支持来源、级别和关键词组合筛选、自动跟随、复制、导出、清空显示及日志目录。反复打开会复用并激活同一个窗口，保留调整后的大小。关闭窗口不停止任务、日志采集或磁盘保存，后台新增消息会继续进入共享会话缓冲，重新打开后仍可查看。

默认“用户日志”显示任务进展、重试、轮次结果和停止原因，右栏实时日志使用相同摘要。按钮内部状态、等待计时采样等信息收在“全部诊断”；“仅看问题”集中显示警告和错误。主列表使用中文级别，并显示消息所属轮次。选中消息后点击“展开详情”，或直接双击消息，可查看完整原文、Seed、推进数、延迟和计时参数；“复制详情”用于提交具体问题。关键词也可匹配详情内容。

同一运行、轮次与阶段中，相邻的同类计时采样或重试会合并显示累计次数，详情保留首次和最近一条记录；每次原始输出仍按原样写入已启用的磁盘日志。普通的“未找到目标”属于本轮结果，可自动重试的失败显示后续尝试次数；需要人工确认的判闪结果会明确提示。

完整日志汇总应用、自动定点、自动 TID、Seed 捕捉、OCR 和伊机控等来源。自动任务页面及其状态栏入口定位当前运行与轮次；实时区入口只带来源，轮次详情使用所选历史记录，三种筛选上下文互不混淆。“帮助 -> 运行日志 -> 查看完整日志”显示整个会话。窗口最多保留当前会话最近 10,000 条；“清空显示”只清空完整日志的当前视图，不清空共享缓冲、不影响实时区，也不删除磁盘文件。窗口关闭或最小化期间新增的警告、错误会在实时区和状态栏显示待查看数量，打开完整日志后清除提醒。

高频脚本输出在主列表显示输出摘要，超长输出的详情只保留有限的末尾内容，并提示“输出显示已截断”。需要保存完整输出时请启用磁盘日志；输出只写入文件一次，界面的截断不会影响已启用的文件保存。“用户日志”复制、导出当前摘要，“全部诊断”复制、导出当前保留的原始内容和参数。

磁盘日志默认自动保存，按自然日写入：

```text
logs/run_YYYY-MM-DD.log
```

同一天多次启动会追加到同一个文件，只保留最近七个自然日。可在完整日志窗口或“帮助 -> 运行日志”中关闭自动保存，也可打开日志目录；两处开关保持同步。关闭自动保存只停止写文件，不会停止当前会话日志收集。

启用磁盘日志时，界面心跳延迟超过 2 秒会自动保存 Python 线程堆栈、时间与版本信息到 `logs/ui_stall_YYYY-MM-DD_pid-N.log`，同一次卡顿只记录一次，诊断文件同样保留七个自然日。诊断不记录画面或局部变量。关闭日志保存后不再采集或写入卡顿诊断。

## 自动更新

应用默认在每次启动后静默检查正式版更新，仅发现新版本时提示。可在“帮助 -> 启动时自动检查更新”中关闭；“帮助 -> 检查更新…”始终可以手动使用。

- 优先下载只包含变化文件的增量包，并校验 Release 中的 SHA-256。
- 主程序退出后由独立升级器替换文件并重新启动；新版未确认成功或替换失败时自动恢复旧版。
- 没有连续增量链或需要修复安装时，软件会引导前往 Release 页面手动下载完整 zip。
- 用户修改过的 `script`、运行日志、Project_Xs 配置和自定义眼图不会被强行覆盖。
- 新版默认文件需要与用户修改并存时，会写为 `.new-v<版本>`；同名副本已存在时继续追加编号。

升级到 v3.4.0 后，原 Seed 手动工具、OCR 设置与手柄入口的位置发生变化，见[工作区](#工作区)；旧分步引导不再启动，QQ 绑定教程保留。旧版御三家默认 4 秒判闪阈值迁移为 5 秒，其他自定义阈值和已有 delay 保留。若修改过 `script/御三家反查.txt`，请对照 `.new-v3.4.0` 副本合并需要的修正；「御三家全自动」始终绑定随包的内置脚本，不读取这份用户脚本。轮次快照属于当前会话，升级关闭软件前请导出需要保留的记录。

## 使用注意

- 工具依赖 Windows 桌面环境、采集卡、游戏画面、串口状态和脚本时序；实机运行前请先分别验证视频源、眼图和短按键脚本。
- 系统休眠会中断视频和自动流程；关闭显示器也可能受采集驱动或 OBS 状态影响。捕捉保活只负责有限的眨眼捕捉阶段，不是全程防休眠机制。
- 基准 delay、动态 delay 策略、脚本 `_闪帧`、判闪阈值和画面响应时间需要按设备校准，尤其不要直接把其他设备的参数当成最终值。
- 更新器会保留用户脚本，但重要自定义脚本仍建议自行备份；`third_party` 目录用于上游参考，不建议直接修改业务逻辑。
