# 自动定点报错后跨轮日志模拟记录

验证日期：2026-10-26（北京时间）。基于当前本地代码运行，包含尚未发布的日志调整。

此前已有状态机重试测试和单条日志展示测试，但展示测试将轮次固定为第 1 轮。这次补齐从主窗口启动、真实工作线程报错、历史记录归档、自动进入下一轮，到恢复后正常结束的串联核对。

本次实际使用主窗口启动入口、自动定点状态机、Worker / QThread、历史事件发布、共享日志缓冲、实时日志、完整日志筛选和详情切换。设备连接、脚本执行、识别返回值和时钟使用模拟服务，通知发送替换为内存记录。

以下正文直接来自这四次运行后的用户日志，没有手工改写文案。为方便审阅，附加序号、轮次、中文级别和来源，省略记录时间。等待进度沿用界面的合并规则，只显示最新状态；这不是每次内部采样的磁盘日志。

4 个串联场景均通过自动检查；下文保留合计 47 条用户日志，并逐项检查了其中 9 条警告 / 错误的默认详情和原始诊断。

## 已核对的行为

- 第一轮失败日志仍属于第一轮，第二轮的开始、测种结果和候选信息属于第二轮；轮次由实际历史事件和进度回调决定。
- 第一轮、第二轮的完整日志筛选互不混入；第二轮没有新增警告或错误，恢复后的进度与结果正常显示，第一轮警告仍保留在历史日志中。
- 同一次测种失败只显示一条重试警告；历史记录中的转发副本保留为诊断记录。
- 用户正文及默认详情不显示内部组件名、异常类型、路径或原始计时；单纯测种失败不补成超时或框选问题。
- 每条警告 / 错误主动打开原始诊断后能查到模拟异常原文，磁盘日志也保留原文。
- 连续五次测种失败与测种脚本异常分别停止任务，保留对应停止提示。

## 仍需审阅的文案

第二个场景中，校正重试用尽后实际显示“本轮未能继续，正在重新测种”。它没有在这一句中说明“校正连续失败”；前一条日志才是校正重试提示。下文保留当前实际输出，方便继续确认文案。
