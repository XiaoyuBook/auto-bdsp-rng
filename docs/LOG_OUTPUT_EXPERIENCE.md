# 右下角日志与默认详情检查

本次检查覆盖实时日志的共享入口、自动定点与自动 TID、手动/配置测种、原生与兼容脚本结果、视频、识别、连接、键盘控制、配置/脚本保存、历史记录及通知。

普通日志保留步骤、结果、范围和后续动作；问题日志直接展示已确认的原因。默认详情按具体原因、相关原因、脚本位置、处理建议、记录信息排列，完整异常类型、内部名称、路径及参数仍需主动打开“原始诊断”。没有证据时明确写出原因尚未确认，不把测种失败等同于采集超时。

以下例子由当前日志展示代码生成。异常输入主动构造；脚本错误使用真实引擎执行。它们验证展示行为，不代表已复现长时间运行后的测种故障。

## 验证边界

- `tests/test_log_explanations.py` 覆盖具体原因、未知原因、原因经过、详情复制与切换，以及四个脚本结果入口；还检查脚本线程、自动脚本异常信号、闪光判定校准的原因传递，以及常规和较小窗口中关键详情无需滚动即可看到。真实脚本引擎产生语法/运行错误，通过实际日志控件展示；自动任务测试使用真实 Worker 和收尾路径，设备与通知用模拟替代。
- `tests/test_log_recovery_flow.py` 保留失败后进入下一轮、校正重试、连续失败保护、脚本失败直接停止的真实 UI/Worker/Runner 集成验证；测试注入故障，不宣称真实设备故障复现。
- 原始日志文字和异常原因链继续保存；失败的脚本不会被记录为正常完成，也不会进入测种失败重试。
- 没有修改 Seed 求解、推进计算、脚本动作、失败重试策略和轮次上限。
