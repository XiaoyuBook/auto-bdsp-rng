# 右下角日志与默认详情检查

本次检查覆盖实时日志的共享入口、自动定点与自动 TID、手动/配置测种、原生与兼容脚本结果、视频、识别、连接、键盘控制、配置/脚本保存、历史记录及通知。

普通日志保留步骤、结果、范围和后续动作；问题日志直接展示已确认的原因。默认详情按具体原因、相关原因、脚本位置、处理建议、记录信息排列，完整异常类型、内部名称、路径及参数仍需主动打开“原始诊断”。没有证据时明确写出原因尚未确认，不把测种失败等同于采集超时。

以下例子由当前日志展示代码生成。异常输入主动构造；脚本错误使用真实引擎执行。它们验证展示行为，不代表已复现长时间运行后的测种故障。

## 自动流程逐阶段核查（2026-11-06）

本轮新增 54 项验证，补查自动流程中的阶段归属、恢复后的原因传递及最终停止方式。以下是已验证的提示和事实摘录，省略时间、来源和部分通用建议；表中的文件、识别和连接异常均由测试注入，不代表真实设备故障复现。

| 阶段或结果 | 用户可见的提示与定位依据 | 实际后续处理 |
| --- | --- | --- |
| 启动准备 | 自动定点／自动 TID 未能启动；未找到所需文件。启动异常保留具体原因，不再提前转成没有原因链的普通文字。 | 不启动 Worker |
| 目标搜索异常 | 目标搜索失败，流程已停止；显示已确认的异常原因、最近记录推进及搜索上限 10,000 帧。 | 停止，不误报为脚本错误 |
| 搜索没有候选 | 本轮没有可用目标；显示当前可达候选为 0、搜索范围，以及扩大范围或放宽筛选的建议。 | 按实际轮次设置换轮或结束 |
| 过帧执行异常 | 过帧脚本执行失败，流程已停止；如已确认断连，则直接说明串口不可用或连接已断开。 | 只显示一条面向用户的终止错误 |
| 过帧后重新测种失败 | 测种失败（连续 1/5），将重新运行测种脚本；过帧脚本已完成，失败发生在重新测种阶段。具体原因有证据才补充。 | 从测种脚本重新开始，不把过帧完成当作测种成功 |
| 位置校正重试 | 校正失败，准备第 2/2 次尝试；本次校正未找到匹配的推进位置。 | 在当前阶段重试 |
| 校正后补救测种 | 位置校正连续 2 次失败，正在重新测种补救；保留校正原因，并说明旧目标已清除、补救最多尝试 2 次。 | 成功后按新 Seed 搜索；失败后按轮次设置换轮或停止 |
| 补救发生新错误 | 补救测种连续 2 次失败；例如新错误为文件缺失，默认详情优先显示文件缺失，前序校正异常作为相关原因保留。 | 不把前序校正原因冒充本次补救失败原因 |
| 过场脚本与过场校正 | 分别使用“过场脚本执行失败”和“过场校正失败”；校正提示保留尝试次数。 | 能重试时说明重试，达到轮数上限时明确停止 |
| 错过撞闪时机 | 已错过目标，正在重新搜索；显示当前推进、目标推进和脚本启动点。 | 放弃已错过目标，再筛选可达目标 |
| 判闪取帧或文字识别异常 | 判闪失败，流程已停止；原因区分读取画面超时、判闪文字识别失败等。 | 不再误归类为撞闪脚本本身执行失败 |
| 判闪关键词超时 | 明确未在限定时间内识别到第一个或第二个判闪关键词；未获得完整计时，不宣称确认未出闪。 | 保留原策略：需人工确认的目标停止；普通目标按设置继续，并以警告显示结果未确认 |
| 反查服务异常 | 自动反查失败，本轮结束；显示具体异常，说明本轮未取得反查结果。 | 按轮次设置继续或结束；测试验证下一轮可正常反查 |
| 反查能力值识别不完整 | 已尝试 3 次，均未识别到完整六项能力值；确认能力页及识别区域。 | 不产生 delay 样本，保留原设置 |
| 反查能力值不合法 | 已识别到能力值，但无法换算成合法个体值范围，未执行匹配搜索；核对能力值、种类和等级。 | 不把未执行搜索写成搜索无结果 |
| 反查搜索无匹配 | 已识别到能力值，但目标推进前后 500 帧内未找到匹配个体；核对识别结果、目标及范围。 | 不产生 delay 样本，保留原设置 |
| delay 样本保存异常 | 延迟样本保存失败，本轮继续使用原策略；可直接显示已确认的权限不足等原因。 | 本轮继续 |
| 疑似闪光后的录像异常 | 疑似闪光录像操作失败；保留设备等异常原因，提示人工保存录像并确认游戏结果。 | 继续保持停止和人工确认；原始结果也不再错误声称已录像 |
| 逃跑脚本异常 | 逃跑脚本执行失败，流程已停止；直接说明已确认的原因。 | 不在失败后假装已逃跑并继续校正 |
| TID 识别没有结果 | 区分文字识别没有返回内容、识别结果没有可用的 TID 数字；提示确认 TID 页面和识别区域。 | 停止 |
| TID 延迟反查无匹配 | 未找到匹配的 TID；例如显示识别 TID 12345、目标推进 10、反查范围前后 50 帧、原 delay 2 帧未更新。 | 停止，不错误报告校准成功 |
| 达到轮次上限 | 显示受阻步骤和具体原因，并写明“已达到设定的 1 轮，不再开始下一轮”。 | 不再显示将重新开始的摘要，也不实际开启新一轮 |

新增集成测试使用真实主窗口、QThread/Worker、Runner、日志缓冲、轮次关联、右下角控件及详情切换；设备、识别、时钟和通知传输使用替身。每个故障用例检查用户摘要、默认详情、原始诊断保留及实际重试／停止结果，并检查内部名称、路径和异常类型未进入用户视图。

不能保证未知异常仅凭摘要就能确定根因。无法确认时仍明确写“当前记录未提供可确认的具体原因”，保留完整诊断；也不能据此宣称已经复现或解决连续运行数轮后测种失败、手动重启又恢复的设备现场问题。

## 验证边界

- `tests/test_log_explanations.py` 覆盖具体原因、未知原因、原因经过、详情复制与切换，以及四个脚本结果入口；还检查脚本线程、自动脚本异常信号、闪光判定校准的原因传递，以及常规和较小窗口中关键详情无需滚动即可看到。真实脚本引擎产生语法/运行错误，通过实际日志控件展示；自动任务测试使用真实 Worker 和收尾路径，设备与通知用模拟替代。
- `tests/test_log_recovery_flow.py` 保留失败后进入下一轮、校正重试、连续失败保护、脚本失败直接停止的真实 UI/Worker/Runner 集成验证；测试注入故障，不宣称真实设备故障复现。
- 原始日志文字和异常原因链继续保存；失败的脚本不会被记录为正常完成，也不会进入测种失败重试。
- 没有修改 Seed 求解、推进计算、脚本动作、失败重试策略和轮次上限。
